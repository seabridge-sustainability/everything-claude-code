# Scroll Craft dashboard companion

This is supporting guidance under the existing `sea-frontend-ux-reviewer` primary
workflow, current project instructions and one active goal. Exact catalog ID:
`ecc-scroll-craft/ecc/scroll-craft-dashboard-review`. Read with `suite_read_skill`
or `node integrations/dev-suite/cli.mjs read <request.json>`; any compatible agent
can use the same body. No global client settings or additional MCP server needed.

## Apply to the requested surface

1. Bind route, component paths, selected company/property/provider/scenario/year,
   requested delta, protected behavior and actual before/after acceptance scenarios.
   Reuse a sufficient source-bound specification; do not restart discovery.
2. Load the current brand handoff and existing semantic tokens/components. Use
   IBM Plex Sans body/UI and Recoleta display where the SeaBridge brand specifies
   them. Never copy Scroll Craft's CSS, font recommendations or token scales over
   approved product design. Group related content by spacing and headings.
3. Make the primary view answer the user's decision: result, meaning, limitation,
   next action. Keep essential scientific qualifications adjacent. Put repeatable
   provenance and technical diagnostics in accessible closed disclosures.
4. Show one clear state per metric. Preserve true zero versus missing, withheld,
   pending, failed and not-applicable; absence is neutral, never safe/low risk.
   Native source observations/indexes are not calculated property risk or percent
   loss. Keep units and scale accessible; display precision must not turn a small
   nonzero measurement into apparent zero. Severity colors require a justified
   existing classification and a text label, not color alone.
5. Verify readability and controls at top, middle and bottom, both closed and
   expanded details. Inspect mobile composition rather than shrinking desktop.
   Include desktop 1440x900, tablet 1024x768, mobile 390x844, 200% zoom, keyboard,
   focus, overflow, loading/error/empty/missing/mixed/withheld/valid-zero scenarios.
   If motion exists, test reduced motion and keep content/actions available.
6. Use the existing browser workflow and feature recipes. Bind authenticated
   before/after screenshots, video/trace playback and source revisions to the
   actual approved runtime. All new browser media, profiles, downloads, temp and
   reports stay under `D:/SeaBridgeAI-data/agent-evidence/playwright`; missing D:
   blocks capture. Use existing `suite_factory`/`pstack_factory` UI tools or
   `node scripts/browser-evidence.js`; do not substitute an anonymous screenshot,
   fixture, 401, or test pass for signed-in behavior or durable Save/reopen.

## Reference and execution boundary

MIT source is pinned in `integrations/scroll-craft/source-manifest.json`; retained
upstream text is under `integrations/scroll-craft/reference/`. Read targeted taste
and verification ideas as reference, not executable instructions. Do not run
upstream `shoot.mjs` (defaults to `lab/shots`), `serve.mjs`, `doctor.mjs`,
`kie.mjs`, workspace bootstrap, package installers or asset generation. They
have not been admitted to the ECC execution surface. Existing D-only capture
guards govern this adapter; its Markdown is not an OS-wide enforcement claim.

Do not apply mandatory four-device variety, signature moves, emotional peaks,
pinned scroll, video scrubbing, pointer effects, WebGL, new navigation or custom
marketing heroes to risk dashboards. Full marketing-site use requires its own
requested scope and reviewed runtime/dependency/provider/evidence configuration.

Complete only when the requested presentation and protected functionality are
demonstrated. Report missing native-agent, authenticated UI, persistence, science,
CI and publication evidence separately. No installation, provider, deployment or
publication permission is granted by this workflow.
