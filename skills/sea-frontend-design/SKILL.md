# sea-frontend-design

## Purpose

Build credible, usable, accessible frontend workflows rather than decorative shells.

## When To Call

Use for manageesg-frontend, OpenSeaBri UI, dashboards, reports, charts, forms, filters, AI assistant panels, and frontend reviews.

## Required Inputs

Route; exact component paths; backend caller; available data shape; design conventions; target user workflow; requested delta and protected behavior; before/after acceptance scenarios; desktop/mobile viewports; required UI states. Resolve material ambiguity with `sea-requirements-discovery`, using current source first. A sufficient existing ticket needs no repeated interview or timed ceremony.

## Expected Outputs

Reachable UI; honest loading/empty/error states; responsive behavior; API/state verification notes.

## Dashboard presentation and references

Use current SeaBridge brand assets and semantic tokens, existing Radix/Tailwind/
Recharts components and the [frontend UX standard](../../docs/harness/standards/frontend-ux.md).
Preserve scientific meaning, units and missing states; apply the central copy
budget with qualifications/provenance in accessible i/popovers, not repeated
body text. Record any exact binding visible-attribution conflict for the owner. True zero,
missing, withheld, pending and failed are different states. No arbitrary risk
colors, fake scores, API changes or new component packages to improve presentation.

When reference review is requested, retrieve exact shared ID
`ecc-scroll-craft/ecc/scroll-craft-dashboard-review` through `suite_read_skill` or
the existing dev-suite CLI. It is a supporting typography/responsive/scroll-state
review, not a second orchestrator or a marketing engine. UI/UX Pro Max, Motion Sites
and 21st.dev are optional visual references only; do not generate a new brand,
import components blindly or create per-project design rulebooks. Motion is optional
after readability works, with reduced-motion behavior; missing packages need their
actual reviewed installation approval. Prefer existing components and CSS.

## Mandatory Verification

Every user-facing component/copy/layout/route change requires the central visual gate and the [existing browser workflow](../../agent-tooling/skills/seabridge-browser-autonomy/SKILL.md): source-bound specification before editing, before/after desktop/mobile screenshots and successful video/trace playback on D: only. Missing prerequisites block the affected proof; never substitute a fixture, 401 or screenshot for signed-in behavior/persistence. Check route/menu visibility, API contracts, filter propagation, buttons, text overlap and keyboard flow. Compare approved layout/copy/tokens and call out missing baseline approval; do not redesign adjacent surfaces.

## Failure Conditions

Fail if UI displays fake data as real, buttons are dead, route is hidden unintentionally, charts ignore filters, or claims are not endpoint-backed.

## SeaBridgeAI Sustainability And Data-Integrity Requirements

Sustainability metrics must show provenance or missing status. Demo/mock data must be visibly demo-only.

## Cross-Agent Compatibility Notes

Claude/Codex/Gemini/OpenCode/Cursor/Copilot CLI should follow the same UI gates; use Playwright where available for repeatable proof.

## Superpowers Adaptation

Partially adapts Superpowers brainstorming, writing-plans, TDD, and verification-before-completion into frontend workflow gates.
