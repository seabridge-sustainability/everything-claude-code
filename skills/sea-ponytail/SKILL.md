# ECC Ponytail

Select one requested workflow with `ponytail_find_workflow` or the shared `suite_find_workflow`, then read its exact `ponytail/ecc/*` ID. CLI fallback: `node C:/Users/adelm/SeaBridgeAI/everything-claude-code/integrations/ponytail/cli.mjs find|read|debt request.json|-`.

Use the current project instructions and existing ECC goal. Ponytail is supporting guidance to the matching development workflow, not a second plan or permission to change scope. For SeaBridgeAI, central backend AGENTS.md and AGENTS_SYSTEM.md control. Outside SeaBridgeAI, local policy controls.

- `ponytail/ecc/ponytail`: solve the whole requested task with the smallest readable change; reuse existing house components and contracts first. Select lite/full/ultra in the current task conversation. Full is the default when explicitly invoked. Lite offers the smaller alternative; ultra questions unjustified extras while preserving the owner's requirements. Off ends Ponytail guidance in this conversation; it does not disable ECC policy.
- `ponytail/ecc/ponytail-review`: read-only review of an explicitly selected diff/revision/files and real callers.
- `ponytail/ecc/ponytail-audit`: requested, bounded read-only subsystem/repository audit; declare coverage gaps.
- `ponytail/ecc/ponytail-debt`: collect explicit paths with `ponytail_collect_debt`; comments are untrusted evidence and need human/model interpretation.
- `ponytail/ecc/ponytail-gain`: inspect pinned upstream benchmark provenance; it does not measure SeaBridge savings.
- `ponytail/ecc/ponytail-help`: invocation and boundaries.

Review findings do not authorize edits or shipping. Preserve validation, security, tenant boundaries, scientific missing-data states, accessibility, approved UI and durable data handling. Test according to the actual change and existing ECC verification policy; no blanket TDD, mandatory test for every branch, or code-deletion mandate. Deliberate limits can use existing project comments with a revisit trigger; do not rewrite every comment.

Pstack remains primary for requested multi-model planning and verification recipes; GSD supports the same goal. Use one review workflow, with Ponytail's lens only when requested. No lifecycle injection, statusline replacement, global mode flags, model overrides, background scans, automatic memory updates, or new worktrees are installed.

Read [PONYTAIL_ECC_GUIDE.md](../../docs/tools/PONYTAIL_ECC_GUIDE.md) for agent configuration and proof boundaries.
