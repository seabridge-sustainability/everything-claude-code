# Senior engineering workflow

This is a compatibility entry for the existing ECC execution loop. Current central backend AGENTS.md/AGENTS_SYSTEM.md and the latest owner request control scope and permissions.

1. Identify the requested outcome, preserved behavior and observable acceptance. Apply Karpathy's simplest design and surgical edits. Inspect source before asking; use sea-requirements-discovery only for material ambiguity or a requested Grill Me session.
2. For long/resumed/cross-repo/high-risk work, use goal-default and the existing goal records. Otherwise state the small acceptance check directly. Do not create a competing plan or additional product rulebook.
3. Use sea-skill-map and the canonical routing manifest for one primary discipline. Reuse existing components and contracts; implement a small functional slice. Test-first is useful when it exposes the defect, not a universal ritual or fixed coverage target.
4. Verify affected behavior with existing tests and the intended runtime where required. sea-verify-seabridge maintains reusable recipes and deterministic factory contract/fuzz checks; a readiness probe, fixture or self-report does not establish authenticated persistence or science. At a feedback checkpoint, read admitted metadata with the same factory and form a sanitized version-bound proposal for this goal; local claims are not repository ownership or permission to implement.
5. Review consequential uncertainty with sea-adversarial-review when needed. Use independent read-only reviewers only when authorized; label self-critique as degraded and retain unresolved findings. No second review chain or model call by default.
6. Run the existing final-claim gate for a controlled task and report changed, verified, unverified and remaining outcomes. Preserve normal commit/push/release gates and covered authorization; do not repeat approval for included steps.

Detailed procedure and tool selection are delegated to the selected skills and existing ECC policy. This entry owns no extra phases, mandatory interview, full-suite loop, model preference, worktree requirement or automatic shipping behavior.
