## How to approach a module change

Find the exact route in the inventory below, follow its imports and typed API client, and inspect the corresponding backend registration, schema, service and existing tests. Describe the requested before/after behavior and what must stay unchanged before editing. Preserve current layout, copy, navigation, filters, permissions, selected company/property, scientific states and saved-source identity unless the user requested their change. A UI bug is not permission to rebuild its surrounding module.

Use one primary workflow: requirements discovery for unresolved material ambiguity; frontend design/review for UI implementation; systematic debugging for a demonstrated defect; verification maintenance for a recurring missing check. Pstack planning and Ponytail review may support a consequential change but do not start competing plans or blanket simplification passes. Grill Me is useful when the goal is unclear, not a mandatory interview for every label or spacing fix.

For visible changes, the proposed acceptance packet records exact route/components, current behavior, approved baseline, protected layout/copy/data, interactions, viewport/state cases and verification recipe. Evidence should cover the changed workflow and adjacent regressions. Screenshots prove appearance; API responses prove their own contract; durable Save/reopen and exports require their own receipts. Mocked E2E screenshots do not prove real data persistence.

**Browser media storage:** following the owner's latest instruction, capture video, screenshots, traces, browser profiles and media-containing Playwright/HTML reports only under `D:/SeaBridgeAI-data/agent-evidence/playwright/<repo>/<task>/<run>/`. Lightweight redacted receipts may stay in ECC and reference D: paths, hashes and sizes. Verify the resolved path, disk identity and capacity before capture; unavailable D: blocks capture with no C:/E:/temporary fallback. Do not move historical evidence or change running browsers without a separate scoped operation. The audit defines how to implement this; existing runners still need reconciliation.

## Business modules and submodules
