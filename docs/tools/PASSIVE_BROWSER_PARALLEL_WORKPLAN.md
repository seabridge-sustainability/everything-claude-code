# Parallel passive browser operations: activation checklist

The current coordinator can perform the ROOT role under Alejandro's existing
instruction. ROOT is not intrinsically the Windows chat. The two passive Python
producers accept `rea-greenly-lca-*` and `rea-persefoni-scope3-*` actors, require
normal ECC registration/original-goal/output admission and source-owner closure,
and retain their own native, privacy, input, route and finite-deadline guards.
Their retained scope reviews can be reused when the exact original pins and scope
match. No new human approval is required merely because a different authorized
coordinator performs those checks. Existing private capture authority is separate.

This plan covers the existing fixed passive operations. Both forbid navigation,
click, focus and capture commands. Actual route-changing navigation needs its own
matching operation review/admission; this adapter does not broaden either scope.
The old capture `heavy-check` key did not cause these passive producers to run
through ROOT. They did not use that queue. Their missing integration was current
navigator custody and a per-target claim around their existing dispatch.

## Execute through the existing witnessed dispatcher

- [ ] ROOT builds both adapters with its own held callbacks. Workers cannot
  supply approving callbacks or substitute source paths. `assertWrite` must check
  each actor's exact job path and the normal machine-ledger write capability.
  `verifyAdmission` rechecks current normal actor/goal/output/source admission;
  `verifyCustody` rechecks the real navigator and target owner, including legacy
  operators; `verifyNativeIdentity` rechecks the complete browser/profile epoch.
  All three callbacks must explicitly handle the `release` phase without treating
  expiry as cessation. `readTelemetry` is the existing trusted live RAM sampler.
- [ ] Supply the existing **asynchronous**, bounded, independently witnessed
  producer dispatcher. It must run only the provided `/usr/bin/python3` plus the
  exact pinned producer path, preserve existing native containment, and return
  `{ externalWitness, operationResult }`. It must not use a blocking spawn that
  serializes the second call. `confirmStopped` freshly verifies the external
  producer, group and native child cessation against the exact actor/nonce.
- [ ] Invoke the following API from that reviewed controller. The module itself
  neither supplies authority callbacks nor launches anything on import:

```js
const { createPassiveTargetAdmission } = require(
  '/home/ubuntu/SeaBridgeAI/everything-claude-code/scripts/lib/passive-browser-target-admission.js');
const greenly = createPassiveTargetAdmission(greenlyRootHeldContext);
const persefoni = createPassiveTargetAdmission(persefoniRootHeldContext);
const results = await Promise.allSettled([greenly.run(), persefoni.run()]);
// A rejected dispatch may have launched work. Keep its claim, inspect the
// independent witness, then call adapter.reconcile(witness, 'cancelled') only
// when its existing gates and complete cessation verification pass.
```

Each context contains `repositoryPath`, `assignmentBytes`, `assignmentSHA256`,
`assertWrite`, `readTelemetry`, `verifyAdmission`, `verifyCustody`,
`verifyNativeIdentity`, `confirmStopped`, and `dispatch`. The adapter computes the
canonical repository machine index itself. Its per-job `target-queue.json` records
the actual actor, resource and lease; tokens remain internal to the adapter.

## Live acceptance and recurring use

- [ ] Observe genuinely overlapping monotonic producer/native operation intervals
  for the two different admitted existing targets. Two source reviews or queue
  claims alone are insufficient. Do not add sleep to manufacture overlap.
- [ ] Confirm a competing same-target actor is refused before browser dispatch;
  this negative check requires no conflicting browser command.
- [ ] Retain the allowed boolean-only outputs, original guard results, current
  source pins, native epoch and independent closure/custody-return receipts.
- [ ] Verify Chrome process start epoch, CDP endpoint and profile singleton remain
  unchanged; preserve shared focus/foreground serialization and all private tabs.
- [ ] REA publishes observed overlap or the exact failed gate through its existing
  monitored report. Mark live parallelism complete only after this evidence.
- [ ] For every later wave, reuse the adapter and reviewed unchanged scope but
  issue fresh actual owner/nonce/expiry/checkpoint/admission. Unknown custody,
  stale telemetry or expired claims fail closed; expiry never permits takeover.

Multiple subagents and different eligible targets can operate concurrently within
available native capacity and resource limits. Neither this adapter nor the
larger agent limit promises unlimited throughput or permanently valid browser
authority. A blocked target should not prevent independent eligible targets or
non-browser work from proceeding.
